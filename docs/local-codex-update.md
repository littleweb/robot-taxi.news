# 本地 Codex 晨间采编

当前路径不需要 LLM_API_KEY 或云端持久数据库。由这个聊天的本地 Codex 定时任务负责搜索和写作，GitHub 只用临时数据库恢复公开内容并生成静态站。不会把 Codex 登录信息传到 GitHub。Codex 使用当前账号额度，不能承诺无用量限制；本地不代表离线模型。

## 每日流程

每天北京时间06:30开始，目标08:00前完成。先确认本地工作区与 GitHub 登录可用，阅读本文件和 AGENTS.md。

1. 使用联网搜索并打开原文，检查最近24小时的 Robotaxi 业界动态、规模、融资、全球布局、技术和国内进展。优先官方公告、监管与财报，补充可靠媒体和 X、YouTube、Facebook 可公开访问内容。区分计划、试验、商业运营、日期与统计口径。社交平台无法访问时记录覆盖缺口，不声称已全量抓取。
2. 与 `site/editions/` 和 `site/reviewed-bootstrap.json` 比较去重；同一事件优先一手来源。目标10–20条有价值消息，有多少真实新进展就收录多少，绝不为凑数重贴旧闻。原日期不能改成今天。可补独立图像、视频链接，媒体版权归来源，禁止生成假现场图。
3. 写入 `site/editions/YYYY-MM-DD.json`，结构参照现有一期与 `modules/robotaxi/edition.ts`。`date` 是上海出刊日，`researchedAt` 是真实核对完成时间。每条记录具有原文URL、来源名、日期、中文标题摘要、解读、分类、主体、区域、标签及简短证据 `quote`；可加 `image` / `video` 原链接。quote宜为原始标题或极短引文；摘要自己写，不复制全文。不含个人信息或凭据。
4. 运行 `node modules/robotaxi/validate-editions.ts` 和类型检查；只提交本轮内容文件，不夹带其他改动。推送至 littleweb/robot-taxi.news 的 main，再执行 `gh workflow run publish-pages.yml --repo littleweb/robot-taxi.news -f mode=codex`。已授权自动同步和公开发布，无需每期再询问。
5. 等待对应工作流完成，打开线上日报与 export-manifest，核对出刊日期、新闻日期、链接、配图和静态导航。如果失败保留上一版，不把导出时间冒充新闻更新时间。记录具体失败原因，不能宣布更新成功。

临时数据库在构建时先导入首版核实资料，再按日期恢复所有 Codex 期刊。历史日报从其公开来源记录重新编排，保留原始出刊日与核对时间；不是重新采集旧新闻。文章ID依据URL保持稳定，首版已发布链接沿用原ID，避免每日重建改变已分享的链接。数据经原材料入口、审核覆盖与公开读取层，Codex 不冒充原模型五维评分。页面注明由 Codex 检索、未经人工逐条审阅。

目前没有付费采集和模型调用，原安全阀保持关闭。周报和月报入口保留，首阶段不伪造尚未生成的周期报告。

## 本机运行条件

电脑开机联网、Codex 可运行且登录有效、账号有可用额度，项目目录保持可访问，GitHub 登录具有推送和触发工作流权限。休眠、退出应用或额度耗尽可能导致延迟。若严格要求08:00前完成，应将同一 Codex 任务迁至常驻执行主机并配置告警。

本机 Node24 位于 `/tmp/robotaxi-runtime/node_modules/node/bin`，若该临时目录失效应安装正式 Node >=24.11，勿降低运行版本。GitHub 工作流自动安装Node24。
